Adversary Emulation Test Plan · Draft for Scoping

Which attacks pass the boundary between SDWAN and the KVDC / IPDC data centres?

A structured breach-and-attack-simulation plan for the GITN MyGovNet environment. Every technique below is framed as a control test: it names the allowed path it abuses, what security control should stop or catch it, and the signal the blue team should see. A technique that gets through silently is a finding, not a win.

Encrypted C2 & tunnelling over 443

Since 443 is permitted inbound and outbound, the first question is whether the boundary inspects what rides inside TLS or only that the port is 443. Each tunnel below reaches the internet with no inbound firewall change, so it also validates the reverse (DC-initiated) egress path.

DNS covert channels & resolver bypass

DNS is the other universal egress. The tests split into two goals: (1) can an endpoint bypass the internal resolver entirely (DoH/DoT), blinding DNS logging and sinkholing; and (2) can DNS itself carry a covert channel for C2/exfil.

DNS-over-HTTPS to public resolvers

High

Resolve via Cloudflare 1.1.1.1, Google, Quad9, NextDNS over 443 — internal DNS filtering, logging and sinkholes are bypassed because queries never touch the corporate resolver.

02

Execution framework

Assumed-breach, run as a purple-team exercise so blue-team detection is validated live rather than after the fact.

1

Boundary mapping

Confirm the two footholds; enumerate what actually traverses SDWAN→DC and DC→SDWAN (Family D sweep). Baseline the ruleset against documentation.

2

Egress channel discovery

Walk Families A & B — 443 tunnels, LOTS C2, DoH, DNS tunnelling. Record every channel that establishes and whether it was seen.

3

C2 & evasion

Stand up C2 on the surviving channels; layer Family G realism (malleable profiles, jitter) to test detection under load.

4

Segmentation & lateral

Pivot via 443 SOCKS and east-west techniques (Family D); demonstrate reach to services that should be isolated.

5

Exfiltration

Move marked canary data over each channel (Family E); measure DLP/analytics catch rate and volume thresholds.

6

Detection validation & report

For every test, record verdict — Blocked / Detected / Passed-undetected — map to the control owner, and file each pass-through as a finding with remediation.

Tooling

  • BAS / automation: MITRE Caldera, Atomic Red Team, Prelude Operator; commercial BAS (AttackIQ, SafeBreach, Scythe).
  • C2: Sliver, Mythic, Havoc; Cobalt Strike where licensed.
  • Egress / tunnels: cloudflared, ngrok, chisel, gost, wstunnel, iodine, dnscat2, egress-assess.
  • Recon: nmap/masscan, httpx, tlsx across the boundary.

Verdict & reporting

  • Blocked — traffic denied at the boundary. Control confirmed.
  • Detected — passed but alerted. Detection confirmed; consider prevention.
  • Passed-undetected — the finding. Log path, control gap, owner, fix.
  • Deliver as an ATT&CK coverage heatmap plus a prioritised remediation list.
03

Rules of engagement & safety

Non-negotiable before any execution

  • Written authorization from GITN and each participating agency, naming in-scope zones, IPs, source hosts and the exact test window.
  • De-confliction contact on standby; SOC informed it is an exercise, with a "stand-down" signal agreed.
  • Synthetic canary data only — never exfiltrate real citizen or government records; use marked tokens that prove reach without disclosing data.
  • No denial-of-service: rate-limit scans and tunnels; avoid actions that could degrade production services.
  • Cleanup & rollback: remove implants, tunnels, scheduled tasks and test accounts; document every artefact created.
  • Handle findings securely: any captured credentials or tokens are treated as sensitive and rotated after the test.

Why this framing

  • Every "bypass" is documented as a control gap with a named remediation — the deliverable is a stronger boundary, not a list of tricks.
  • Common remediations these tests drive: default-deny egress with domain allow-listing, TLS inspection with tunnel/DoH category blocking, forced internal DNS resolver, application-ID (L7) enforcement on 443, micro-segmentation independent of egress, NDR beacon analytics, and DLP with volume-over-time thresholds.
